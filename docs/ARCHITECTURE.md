# Architecture

## Overview
A responsive web application consisting of a React 19 single-page frontend utilizing Tailwind CSS and Material UI, communicating via a REST API with a Flask 3.11 backend. Persistence is managed via PostgreSQL 16 using SQLAlchemy and Flask-Migrate, with JWT-extended authentication and Flask-Bcrypt password hashing securing user registration, flexible login, and protected dashboard access.

## Technology Stack
- React 19 - Frontend UI library
- Material UI v6 - Core component library
- Tailwind CSS v3 - Layout and utility styling
- React Router DOM v6 - Client-side routing
- Axios - HTTP client for API communication
- Flask 3.11 - Backend REST API framework
- SQLAlchemy - Python ORM
- Flask-Migrate - Database migrations
- Flask-Bcrypt - Password hashing
- Flask-JWT-Extended - JWT authentication
- PostgreSQL 16 - Relational database engine
- Gunicorn - Production WSGI server

## Folder Structure
- backend/ - Flask application root
- backend/app/ - Application factory, config, and extensions
- backend/app/models/ - SQLAlchemy database models
- backend/app/routes/ - REST API route blueprints
- backend/app/services/ - Business logic and validation helpers
- backend/migrations/ - Alembic database migration scripts
- frontend/ - React application root
- frontend/src/ - React source files
- frontend/src/components/ - Reusable shared UI and layout components
- frontend/src/pages/ - Page-level views (Home, About, Contact, Dashboard, Login, Register)
- frontend/src/services/ - Axios API client configuration
- frontend/src/context/ - React Context for authentication state

## Data Model
- User: id (Integer, PK), email (String, Unique, Indexed), username (String, Unique, Indexed), password_hash (String), created_at (DateTime); no child relationships.

## API Conventions
- Base URL prefix: /api
- Endpoint naming: plural nouns for collections (e.g., /api/auth/register, /api/auth/login)
- Request/Response format: JSON for all payloads
- Authentication: Bearer token in Authorization header (Authorization: Bearer <JWT>) generated by Flask-JWT-Extended
- Success response structure: JSON object with data payload and/or message
- Error response structure: JSON object containing 'error' string and optional 'details' object
- HTTP status codes: 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 404 Not Found, 409 Conflict, 500 Internal Server Error

## Coding Standards
- Python: PEP 8 style guide, snake_case for variables/functions, PascalCase for classes
- JavaScript: ES6+ syntax, camelCase for variables/functions, PascalCase for React components
- Error handling: Try-except blocks in backend routes with rollback on database exceptions; try-catch with toast/error banners on frontend
- Validation: Server-side validation for email format and password policy (min 8 chars, 1 uppercase, 1 digit, 1 special character) mirrored on frontend
- Security: Passwords hashed via Flask-Bcrypt; JWT stored securely in frontend memory/state or secure storage; CORS enabled strictly for allowed origins
- Logging: Standard Python logging module configured for backend requests and error traces
- Testing: Unit tests for backend auth services and database models using pytest

## Shared Components
- backend/app/__init__.py - Flask application factory and extension initialization
- backend/app/config.py - Environment configuration and database URI setup
- frontend/src/services/api.js - Configured Axios client with request interceptors for JWT injection
- frontend/src/context/AuthContext.js - Shared authentication state provider and hooks
- frontend/src/components/Layout.js - Responsive navigation bar and main wrapper layout (REQ-001, REQ-002)
- frontend/src/components/ProtectedRoute.js - Route wrapper enforcing authentication redirection (REQ-009)
